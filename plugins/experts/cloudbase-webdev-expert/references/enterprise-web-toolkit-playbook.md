# 企业 Web 工具落地 Playbook

面向"不用写代码也能做出趁手工具"和企业统一接入两类场景的模式沉淀。客户案例中的企业专属信息（域名、联系人、审批流）已泛化，落地时以客户自己的规范为准。

## 一、典型场景清单

这些场景已被反复验证"说清需求就能做出来"，可作为需求澄清时的示例引导：

| 场景 | 核心数据 | 权限要点 |
| --- | --- | --- |
| 客户跟进提醒 | 客户档案、跟进记录、下次跟进时间 | 销售看自己的，主管看全组 |
| 业绩统计看板 | 订单 / 业绩数据 | 只读为主，按部门隔离 |
| 排班 / 请假 | 班表、请假单 | 员工提交自己的，管理员审批导出 |
| 项目进度追踪 | 里程碑、负责人、风险 | 团队共享，负责人可改 |
| 内部门户 / 周报 | 文档链接、汇总表 | 全员只读 + 个人可提交 |
| 客户演示 / SaaS MVP | 业务数据 + 注册用户 | 注册登录，租户间数据隔离 |

## 二、企业统一接入模式

已采购 CloudBase 的企业，接入通常遵循以下模式（具体以企业 IT 规范为准）：

1. **统一采购、统一凭证**：SDK 和访问凭证由企业 IT 配置好，开发者（含 AI Agent）无需自行申请密钥；新工具直接复用
2. **审批开通账号**：使用者按企业流程申请开通，注明用途；账号与用途绑定便于审计
3. **域名对内对外隔离**：
   - 内部工具用 `int-` 前缀子域名（如 `int-hr-leave.company.com`），仅内网 / 内部身份可访问
   - 对外演示用 `demo-` 前缀子域名，公网可访问，**严禁存放真实客户或业务敏感数据**
   - 命名规范通常为 `前缀 = 部门/项目缩写-用途缩写`；自定义域名绑定走企业审批，一般不支持 CLI/API 自动绑定
4. **切换 Agent 不换后端**：更换 AI 工具（不同 IDE / CLI）只需改参数，SDK 与凭证不变，已建的应用和数据不受影响

## 三、非开发者需求描述模板

引导用户按这个格式说需求，一次澄清到位：

```
谁用：哪些角色的人会用（如：销售 / 主管）
做什么：核心流程 1-3 条（如：记录跟进、到期提醒、看统计）
数据：要记录哪些信息（如：客户名、跟进内容、日期）
权限：谁能看什么、谁能改什么
样子：一句话说清界面期望（列表？看板？手机上用吗？）
```

## 四、安全红线

1. 内部工具链接不要公开分享；含敏感数据的工具必须登录 + RLS 控权
2. 对外演示环境用脱敏 / 模拟数据，严禁存真实客户信息
3. 任何密钥（API Key、AppKey）不进前端代码，服务端逻辑放云函数
4. 多角色工具上线前，必须验证"低权限角色看不到别人的数据"

## 五、场景适配判断（什么时候用本专家）

- 只是纯展示页 / 落地页 / 原型视觉稿 → 静态托管即可，不需要数据库，任何静态方案都行
- **要真实数据库、按角色控权、服务端逻辑、数据留在企业自有环境、后续持续迭代** → 本专家 + CloudBase（Web + PostgreSQL + RLS + 云函数）是对的选择
- 拿不准 → 先按 Phase 1 问清"谁用、什么数据、什么权限"，再定方案
