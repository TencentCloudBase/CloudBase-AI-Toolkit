# Kimi Code / Kimi Work 配置指南

Kimi Code（终端 Agent）和 Kimi Work（桌面端，内核同 Kimi Code）可以通过 **Kimi 原生插件** 一次获得 CloudBase MCP 工具和 Skill；也可以手工写 MCP 配置。推荐用插件。

配置后，你可以在 Kimi 对话里直接操作 CloudBase：查库、管云函数、列云存储、看 CloudRun。

**例如：**

- "登录云开发，列出当前环境的云函数"
- "查一下 PostgreSQL 里有哪些表"
- "列出云存储根目录和 CloudRun 服务"

## 前置条件

<details>
<summary><strong>已准备好 Node.js、Kimi Code、云开发环境</strong></summary>

**Node.js：** v18.15.0 或更高。

```bash
node --version
```

**Kimi Code：** 本机已验证版本为 **0.34.0**（2026-08-18）。插件系统仍是 Beta，格式可能变。

```bash
kimi --version
```

**云开发环境：** 参考 [开通云开发环境](../../quick-start/create-env)。需要 `tcb login` 或 CloudBase API Key。

</details>

## 插件格式说明（官方文档 vs 本机）

Kimi 目前有两套插件清单，本仓 **两份都提供**，以本机 0.34.0 能装、AI 能调用为准：

| 清单 | 依据 | 0.34.0 行为 |
|------|------|-------------|
| `kimi.plugin.json` | Kimi Code 文档 + 本机 `kimi-cu` / `kimi-webbridge` | **主路径**。`/plugins install` 读取它。用 `mcpServers` 拉起 `@cloudbase/cloudbase-mcp`。 |
| `plugin.json` | [kimi-cli 官方插件文档](https://moonshotai.github.io/kimi-cli/en/customization/plugins.html)（Beta） | 声明 4 个 `tcb` 包装工具（`command` + JSON Schema）。0.34.0 **忽略** `tools` / `inject`。 |

0.34.0 **没有** `kimi plugin` CLI 子命令。文档里的 `kimi plugin install` 属于旧版 kimi-cli。当前安装入口是 TUI 斜杠命令 `/plugins install`。

官方建议：简单脚本用 plugin tools，持续服务用 MCP。CloudBase 属于后者，所以 0.34.0 走 MCP；`plugin.json` 只覆盖 kimi-cli 兼容面。

源码目录：仓库 `config/kimi-plugin/`。

## 方式一：安装 Kimi 原生插件（推荐）

在 Kimi Code TUI 中执行（路径换成你的仓库绝对路径）：

```text
/plugins install /absolute/path/to/CloudBase-MCP/config/kimi-plugin
```

然后 `/reload` 或开新会话。插件会被复制到：

```text
~/.kimi-code/plugins/managed/cloudbase/
```

验证：

```text
/plugins list
/plugins info cloudbase
```

对话里说：

```text
检查 CloudBase 工具是否可用
```

或：

```text
登录云开发
```

从 GitHub 子目录安装（Kimi 支持 git-url + 子路径）：

```text
/plugins install https://github.com/TencentCloudBase/CloudBase-MCP.git/config/kimi-plugin
```

若你的 kimi 二进制仍有 `kimi plugin` 子命令（旧 kimi-cli），可以用：

```bash
kimi plugin install /absolute/path/to/CloudBase-MCP/config/kimi-plugin
kimi plugin info cloudbase
```

该路径加载的是 `plugin.json` 里的 4 个 CLI 工具，需要本机已装 `@cloudbase/cli`。

## 方式二：手工配置 MCP（备用）

0.34.0 也没有 `kimi mcp add`。直接编辑 `~/.kimi-code/mcp.json`（格式与 Claude Code 相同）：

```json
{
  "mcpServers": {
    "cloudbase": {
      "command": "npx",
      "args": ["-y", "@cloudbase/cloudbase-mcp@latest"],
      "env": {
        "INTEGRATION_IDE": "Kimi Code"
      }
    }
  }
}
```

保存后 `/reload` 或新开会话。项目级机器配置（`files/kimi.mcp.json` + 模板下载）由后续任务补齐。

也可使用 Open Plugin Spec 的通用安装（写入 `~/.kimi-code`）：

```bash
npx plugins add TencentCloudBase/cloudbase-plugin -y --scope user --target kimi
```

不要和方式一的 native 插件重复装两套 CloudBase MCP。二选一即可。

## 方式一 vs 方式二怎么选

- **要完整 CloudBase 能力（库 / 函数 / 存储 / CloudRun / 认证 / 托管）：** 方式一，让插件拉起 MCP。
- **只要 MCP、不要 Kimi Skill：** 方式二。
- **旧 kimi-cli 且只有 `plugin.json` tools[]：** 安装同一目录，走 4 个 `tcb` 包装工具；复杂编排仍建议配 MCP。

## 常见问题

**Q: `kimi plugin` 提示 unknown command？**  
A: Kimi Code 0.34.0 没有该子命令。用 TUI 的 `/plugins install <目录>`。

**Q: MCP 连接失败 / 工具数量为 0？**  
A: 确认 `npx` 可用、已 `/reload`、网络能拉 `@cloudbase/cloudbase-mcp`。仍失败见 [FAQ](../faq#mcp-显示工具数量为-0-怎么办)。

**Q: 插件装上了但查不了库？**  
A: 先 `tcb login` 或在对话里「登录云开发」。Kimi `inject` 注入的是 LLM 密钥，不是腾讯云凭据。

**Q: 和 CodeBuddy / Claude 插件是同一份吗？**  
A: 不是。Kimi 插件在 `config/kimi-plugin/`，不要改 `config/codebuddy-plugin/`。
